# 形式化レポート: 自然言語証明との差分・難所

本稿は、主要文献 [P](`docs/math/references.md`) の T1・T2 の自然言語証明を Lean 4 / Mathlib
で形式化する過程で生じた差分と難所を記録する。根拠は次の三種類に限定する。

1. `docs/math/degree_labeling.md`（本リポジトリの数学ダイジェスト）の記述。
2. 同一の定理を独立に形式化した二つの参照実装
   （`lean-dogfood-codex/DegreeLabeling/` と `lean-dogfood-claude/DegreeLabeling/`、
   以下それぞれ「codex 版」「claude 版」と呼ぶ）の Lean コード。
3. 両リポジトリの PR 本文・レビューコメント・Issue 上のルーリング。

以下 Part A は Lean 語彙を用いる技術的な差分を、Part B は同じ論点を Lean を知らない
読者に向けて通常の証明の言葉のみで再述したものである。

## Part A — Lean 形式化がもたらす技術的な差分・難所

### A.1 ラベルの 0 始まりと 1 始まりのずれ

[P] のラベル付けは全単射 $f:V\to\{1,\ldots,n\}$ であり、1 始まりの整数を値に取る。
Lean では全単射の余域を `Fin n`（0 始まり）に取るほうが Mathlib の既存の構成と整合するため、
`docs/math/degree_labeling.md` は「頂点 $v$ の源ラベルは $\ell_f(v)=f(v).val+1$ と定義する」
という変換規約を明文化している。二つの参照実装はこの規約を異なる範囲で明示的に使う。

- codex 版 `Contract.lean` は `sourceLabel f v := (f v).val + 1` という関数を独立に定義し、
  `RespectsDegreeOrder`・`RespectsEqualDegreeNeighborSums` の両方をこの `sourceLabel` の比較
  として書く。つまり順序の言明のたびに 1 始まりの値へ明示的に戻す。
- claude 版 `Defs.lean` の `DegreeRespecting` は `f w < f v`（`Fin` の値そのものの比較）と書き、
  `sourceLabel` に相当する変換を導入しない。順序の大小関係は $x\mapsto x+1$ という狭義単調な
  変換で保たれるため、0 始まりのまま比較しても [P] の $f(v)>f(w)$ と論理的に同値になる。

この違いが実際に効いてくるのは、比較ではなく **値そのもの** を使う場面、すなわち T2 の
$2^{f(u)}$ である。claude 版 `Main.lean` の証明対象は
`∑ u ∈ G.neighborFinset v, (2 : ℕ) ^ ((f u : ℕ) + 1)` であり、対応する PR 本文は
「`(2:ℕ)^(f u : ℕ)` は定数倍 2 だけ異なってしまうため、意図的に採用しない」と明記している。
$2^{k}$ は $x\mapsto x+1$ の下で不変ではない（$2^{k+1}=2\cdot2^{k}$）ため、1 始まりの規約を
指数の位置では省略できない。この非対称性——順序比較では 0 始まりのまま済むが、指数の値では
明示的に $+1$ が要る——は、[P] の地の文には現れない実装上の分岐点である。

*出典*: `docs/math/degree_labeling.md` § Lean 表現の規約／
`lean-dogfood-codex/DegreeLabeling/Contract.lean`（`sourceLabel` の定義と使用箇所）／
`lean-dogfood-claude/DegreeLabeling/Defs.lean`・`Main.lean`／
lean-dogfood-claude PR #9 本文。

### A.2 S2: 有限な許容領域の実現

[P] の S2 は「$\mathcal F$ は有限かつ空でないから、$\Phi$ を最小化する $f\in\mathcal F$ を選ぶ」
と述べるのみで、$\mathcal F$（次数順序を尊重する全単射の集合）をどのような Lean の型として
実現するかは指定しない。`docs/math/degree_labeling.md` はこれを「許容な全単射は命題としてで
はなく有限な型または `Finset` として表現しなければならない」と明文化しているが、その実現方法
自体は二つの参照実装で異なる。

- codex 版は `AdmissibleLabeling G := { f : Labeling V // RespectsDegreeOrder G f }` という
  部分型を導入し、その `Finset.univ` 上で最小値を取る（`EdgePotential.lean` の
  `exists_minimal_edgePotential`）。この部分型が `Fintype` になるには
  `RespectsDegreeOrder` の決定可能性が要るが、`Contract.lean` の定義はその都度
  `by classical` を開いており、決定可能性は古典論理由来の非計算的なインスタンスに頼っている。
- claude 版は新しい部分型を作らず、`DegreeRespecting` 自体に対する決定可能述語のインスタンス
  `instance : DecidablePred (DegreeRespecting G) := by unfold DegreeRespecting; infer_instance`
  を `Defs.lean` で明示的に用意し、`Finset.univ.filter (DegreeRespecting G)` という
  `V ≃ Fin (Fintype.card V)` 上の `Finset` を直接最小化の台に取る
  （`Minimiser.lean` の `exists_degreeRespecting_potential_min`）。

どちらも [P] の「有限な候補集合の中で最小を取る」という一文を Lean で検査可能にする点では
同値だが、一方は新しい部分型と非計算的な `Fintype` インスタンスを経由し、他方は既存の型
`V ≃ Fin (Fintype.card V)` 上の決定可能な述語による `Finset.filter` で済ませる。この選択は
[P] の地の文からは一意に定まらない。

*出典*: `docs/math/degree_labeling.md` § S2／
`lean-dogfood-codex/DegreeLabeling/Contract.lean`・`EdgePotential.lean`／
`lean-dogfood-claude/DegreeLabeling/Defs.lean`・`Minimiser.lean`。

### A.3 S4: 入れ替えた 2 頂点間の辺の二重カウント回避——二通りの解決

[P] の S4 は「$v\sim w$ のとき、辺 $\{v,w\}$ は交換の前後で寄与 $ab$ を変えない」と一文で
処理する。$\Phi$ 自体が非順序対（辺）上の和である以上、この一文は「辺 $\{v,w\}$ の寄与を
一度だけ数える」という具体的な作業を暗黙のうちに要求している。二つの参照実装はこの作業を
まったく異なる方法で行い、しかも互いに他方の方法を明示的に排除している。

- codex 版は $\Phi$ を [P] のとおり `Sym2 V` 上の非順序対の和として実装し
  （`EdgePotential.lean` の `edgePotential`）、`SwapPotential.lean` の
  `edgePotential_swapVertices_sub` で辺集合を「$v$ にも $w$ にも接続しない辺」「$v$ にのみ
  接続する辺」「$w$ にのみ接続する辺」「$v,w$ 双方に接続する辺（$v\sim w$ のとき
  $\{v,w\}$ 一本のみ、それ以外は空）」の四つに分割し、最後の部分集合の和が交換の前後で不変で
  あることを個別に示す。この証明はおよそ 230 行に及ぶ。lean-dogfood-codex の Issue #6 上の
  実行可否監査コメントは、この構成を承認する条件として「[P] S4 に対し向き付きあるいは二重和
  による代替を用いていないこと」を明示的に確認している。
- claude 版は $\Phi$ を直接使わず、`Defs.lean` で「順序付き隣接対上の和」
  $\Psi(a)=\sum_v a(v)\sum_{u\sim v}a(u)$ を定義する。ループのないグラフでは
  $\Psi=2\Phi$ になる（各辺が両端点から一度ずつ、計 2 回数えられるため）が、このドキュメント
  文字列は「$\Psi$ と $\Phi$ の関係は定理として形式化されていない。証明経路は $\Psi$ 自身の
  交換恒等式と $\Psi$ 自身の最小化のみを用いる」と明記する。この設計では、辺 $\{v,w\}$ を
  「一度だけ数える」という作業そのものが不要になる——$v$ の項と $w$ の項がそれぞれ独立に
  相手を隣接集合の要素として含むかどうかで場合分けされ、二重カウントの懸念は $\Psi$ の
  定義の対称性に吸収される。対応する PR 本文は「`Sym2` の付随する作業を避けるため」と明記し、
  交換恒等式に定数倍 2 が付くことも合わせて記している。

同じ数学的内容（S4 の交換恒等式）に対し、codex 版は [P] の $\Phi$ をそのまま実装して非順序対
の分割という重い作業を引き受け、claude 版は $\Phi$ の 2 倍にあたる量を新たに導入して非順序対
の分割そのものを回避した。lean-dogfood-codex 側の実行可否監査コメントが「二重和による代替」を
明示的に禁じた対象は、まさに lean-dogfood-claude 側が採用した設計である。これは同じ地の文
から出発した二つの独立な形式化が、同じ曖昧な一文（「辺 $\{v,w\}$ の寄与は交換の前後で変わら
ない」）に対して正反対の解決を選んだ直接の証拠である。

*出典*: `docs/math/degree_labeling.md` § S4／
`lean-dogfood-codex/DegreeLabeling/EdgePotential.lean`・`SwapPotential.lean`／
lean-dogfood-codex Issue #6 実行可否監査コメント／
lean-dogfood-codex PR #13 本文（「No nonadjacency hypothesis, directed proxy, oriented

`lean-dogfood-claude/DegreeLabeling/Defs.lean`・`Swap.lean`／

### A.4 正値性を仮定しない設計、および空グラフ・辺なしグラフの扱い

[P] の T1 は重み列 $c_1<\cdots<c_n$ に正値性を課さない。claude 版 `Main.lean` の PR 本文は
「$S_5$ の符号評価は `hc : StrictMono c` から得られる `a v - a w > 0` のみに依存し、正値性を
一切使わない」ことを確認している。両実装とも重みの型を `StrictMono` な関数 `Fin n → ℝ` として
受け取るのみで、正値性を要求する仮定は導入されていない。

また、[P] は連結性や次数上界を要求せず、頂点数 0（空グラフ）や辺を持たないグラフも対象範囲に
含める。両実装とも `Fintype V` のみを仮定し、`Nonempty V` などの補助的な非空性仮定を加えて
いない。lean-dogfood-codex 側の Issue #4 実行可否監査コメントは「空の `V` が引き続きサポートされ、
露出した可判定性や `Nonempty` の仮定は存在しない」ことを確認事項として明記しており、
lean-dogfood-claude 側の PR #9・#13 本文も同様に「連結性や次数上界の仮定はどこにも使われて
いない」ことを述べる。この確認は自明ではない——S1 の「次数の非増加順に並べる」という構成、
S2 の最小化、S4 の辺の分割はいずれも、頂点や辺が存在しない極端な場合を暗黙に除外していない
かどうかを個別に検査しなければ保証されない。

*出典*: `docs/math/degree_labeling.md` § 対象設定・T1／
lean-dogfood-codex Issue #4 実行可否監査コメント／
lean-dogfood-claude PR #9・PR #13 本文。

### A.5（副次的な差分）S1 の構成: 二つの独立な Mathlib 経路

[P] の S1 は「次数の非増加順に頂点を並べ、同順位は任意に決める」とだけ述べる。この一文は
具体的な Lean の構成を指定しないため、二つの参照実装は互いに異なる Mathlib の補題や構成を
用いて S1 を実装している。

- codex 版 `Admissible.lean` は `OrderDual ℕ ×ₗ Fin (Fintype.card V)` 上の辞書式順序を
  `Fintype.equivFin V` による同順位の一意化（key）と組み合わせ、`LinearOrder.lift'` で
  `V` 上に線形順序を作った上で `monoEquivOfFin` を用いる。
- claude 版 `Minimiser.lean` は `Tuple.sort` を `OrderDual` 値の次数列に適用し、
  `Fintype.equivFin V` との合成として同じ結論を得る。

いずれも「有限の存在」（$\mathcal F\neq\varnothing$）という同一の主張を証明するが、経由する
補題は異なる。これは S1 の一文が特定の構成を強制しておらず、次数順序を尊重する全単射が
（何らかの方法で）存在することだけを要求している——という読みを裏付ける。

*出典*: `lean-dogfood-codex/DegreeLabeling/Admissible.lean`／
`lean-dogfood-claude/DegreeLabeling/Minimiser.lean`。

## Part B — 通常の証明を読む読者のための難所

本節は Part A と同じ論点を、Lean や型理論の語彙を一切使わずに、[P] の証明を手で検証する
査読者が確認すべき点として述べ直す。

### B.1 ラベルが 1 から始まることを指数の計算で使っているか

[P] のラベル付けは頂点に $1$ から $n$ までの番号を割り当てる。番号の大小だけを比較する議論
（「次数が小さいほど番号が大きい」「番号が大きいほうの頂点は……」）では、番号を $0$ から数え
直しても大小関係は変わらないので、この対応のずれは結果に影響しない。しかし T2 のように番号を
指数として使う場合——$2^{f(u)}$——は事情が違う。番号を $1$ ずらして数え直すと、$2^{f(u)}$ は
一律に 2 倍になってしまう。査読者は、証明中で番号を「何番目か」という順序としてのみ使って
いる箇所と、番号の値そのもの（累乗の指数など）として使っている箇所を区別し、後者では番号の
起点（1 から数えるか 0 から数えるか）が結果に直接影響することを確認する必要がある。

### B.2 有限個の候補の中から最小値を選べることの確認

S2 は「次数順序を尊重する全単射の集合は有限かつ空でないから、その中でポテンシャル $\Phi$ を
最小にするものを選べる」と述べる。この一文は二つのことを暗黙に要求している——候補の集合が
本当に有限であること、そしてその集合が空でないこと。後者は S1 で構成的に示されるが、前者
（候補が有限個であること）は、全単射 $f:V\to\{1,\ldots,n\}$ の全体が頂点数 $n$ に対して
$n!$ 通りしかないという事実に依存している。もし議論の対象が有限集合上の全単射ではなく、より
広い（無限の可能性がある）関数の集合であったなら、「最小値を選ぶ」というステップ自体に
コンパクト性や整列可能性など、別の裏付けが必要になる。査読者はこの一文を読み飛ばさず、
「最小値の存在」がどの有限性に支えられているかを確認する必要がある。

### B.3 入れ替えた 2 頂点の間にある辺の扱い

S3–S4 では、次数が等しく番号の大小が逆転している 2 頂点 $v,w$ の番号を入れ替え、その前後で
ポテンシャル $\Phi$ がどう変わるかを計算する。この計算の要は、$v,w$ どちらにも接続する辺——
すなわち $v$ と $w$ が隣接している場合の辺 $\{v,w\}$ 自身——の寄与を、二重に数えることも、
数え落とすこともなく、ちょうど一度だけ扱うことである。[P] は「$v\sim w$ ならば、辺
$\{v,w\}$ は交換の前後で寄与 $ab$ を変えない」と一文で片づけているが、これは $v$ の番号に
対応する重みと $w$ の番号に対応する重みが、辺 $\{v,w\}$ の寄与の中でちょうど入れ替わり、
積としては変わらない（$ab$ のまま）という事実に基づく。査読者はこの一文を、$v\sim w$ の場合
と $v\not\sim w$ の場合とで別々に、かつ他のすべての辺（$v,w$ のどちらか一方にのみ接続する
辺、どちらにも接続しない辺）への影響と混同しないように、手で追い直す必要がある。

### B.4 重みに正値性を仮定していないことの確認

T1 は重み $c_1<\cdots<c_n$ が狭義単調増加であることだけを仮定し、正であることは仮定しない。
証明の要である S5 の一段——ポテンシャルの最小性から $A_v\le A_w$ を導く段——は、
入れ替えた 2 頂点の重みの差が正であること（$a-b>0$、これは狭義単調増加からのみ従う）を使う
のであって、重み自体が正であることは使わない。査読者は、証明のどこにも「重みは正である」
という性質が紛れ込んでいないか、特に符号に関わる段を個別に確認する必要がある。

### B.5 空グラフ・辺を持たないグラフでの成立確認

定理は連結性も次数の上限も要求せず、頂点が一つもないグラフや、頂点はあっても辺が一つもない
グラフも排除しない。これらの極端な場合、結論はほぼ自明に成り立つ（対象となる頂点の組がそも
そも存在しない、あるいは隣接和がすべて空和になる）が、査読者は証明の各段——特に S1 の
「次数の非増加順に頂点を並べる」構成や、S2 の最小化——が、頂点や辺が少なくとも一つ存在する
ことを暗黙のうちに前提していないかを確認する必要がある。

### B.6 同順位の並べ方が一通りに決まらないことの確認

S1 は「次数の非増加順に頂点を並べ、同じ次数の頂点同士の順序は任意に決める」と述べる。この
「任意に決める」という言い方は、S1 が要求しているのが特定の並べ方ではなく、次数順序を尊重
する番号付けが少なくとも一つ存在するという事実だけであることを意味する。査読者は、後続の
議論（S2 以降）が S1 で選んだ特定の並べ方の詳細に依存していないこと——依存しているのは
「次数順序を尊重する番号付けの集合が空でない」という事実のみであること——を確認する必要が
ある。

## まとめ

Part A で挙げた五つの技術的分岐点のうち、A.1（ラベルの起点）・A.4（正値性・空グラフ）は
両実装が同じ選択に収束した一方、A.2（有限領域の実現方法）・A.3（辺の二重カウント回避）・
A.5（S1 の構成経路）は二つの独立な形式化が異なる Mathlib の補題・構成を選んだ箇所である。
特に A.3 は、一方のリポジトリの審査記録が他方の採用した設計を名指しで禁じているという、
最も直接的な分岐の証拠である。Part B の六項目は、これらの分岐点が Lean 特有の産物ではなく、
[P] の証明を注意深く読む人間の査読者が本来手で確認すべき論点であることを示す。
